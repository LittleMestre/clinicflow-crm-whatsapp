# Contribuindo

1. Abra uma issue descrevendo o problema ou sugestão antes de mudanças grandes.
2. Faça um fork e crie uma branch de funcionalidade.
3. Rode `npm run check`, `npm run test` e `npm run build` antes de abrir um pull request.
4. Adicione testes para regras de negócio e integração.
5. Não inclua credenciais, dados de pacientes ou arquivos `.env`.

Convenção sugerida de commits: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`.
